TLS Authentication

English | Japanese

This document describes the settings required for TLS authentication in Gfarm.

TLS authentication in Gfarm uses TLS 1.3, so OpenSSL 1.1.1 or later is required.

There are two types of TLS authentication: tls_sharedsecret authentication, in which the server and client share a secret key, and tls_client_certificate authentication, which uses a client certificate.

Common settings for tls_sharedsecret, tls_client_certificate, sasl_auth and sasl authentication

The following settings are common to the two TLS authentication methods and the sasl and sasl_auth authentication methods.
  • directory containing the Certificate Authority's certificate files
    Required by all clients, gfmd, and gfsd.
    This can be set with the tls_ca_certificate_path directive and defaults to /etc/pki/tls/certs/gfarm.
    This directory format is the same as /etc/grid-security/certificates for GSI authentication, so if your site has already been configured for GSI authentication, simply create a symbolic link with the following command to complete the configuration. 
    # mkdir -p /etc/pki/tls/certs
# ln -s /etc/grid-security/certificates /etc/pki/tls/certs/gfarm

  • directory where CRL files provided by the CA are located
    Used by all clients, gfmd, and gfsd. By default, a CRL file is not mandatory; see the tls_allow_no_crl directive in gfarm2.conf(5).
    This can be set with the tls_ca_revocation_path directive and defaults to /etc/pki/tls/certs/gfarm, the same as tls_ca_certificate_path.
    This directory format is also the same as /etc/grid-security/certificates for GSI authentication, so sites that have already completed the GSI authentication settings can complete the settings by creating the symbolic link described above.
  • the host certificate and the private key for gfmd
    These files are required only on the hosts running gfmd.
    These can be set by the tls_certificate_file and tls_key_file directives in gfmd.conf, and the default file names are as follows:
    host certificate /etc/pki/tls/certs/gfmd.crt
    private key /etc/pki/tls/private/gfmd.key
    For sites that have already been configured for GSI authentication, simply use the following command to create a symbolic link to complete the configuration. 
    # mkdir -p /etc/pki/tls/certs /etc/pki/tls/private
# ln -s /etc/grid-security/hostcert.pem /etc/pki/tls/certs/gfmd.crt
# ln -s /etc/grid-security/hostkey.pem /etc/pki/tls/private/gfmd.key

  • the service certificate and the private key for gfsd
    These can be set by the tls_certificate_file and tls_key_file directives in gfarm2.conf read by gfsd, and the default file names are as follows:
    service certificate/etc/pki/tls/certs/gfsd.crt
    private key /etc/pki/tls/private/gfsd.key
    However, the X509_USER_CERT and X509_USER_KEY environment variables take precedence over the tls_certificate_file and tls_key_file settings, respectively. When gfsd is configured using the config-gfsd command, the tls_certificate_file and tls_key_file directives have no effect, because the gfsd startup script sets these environment variables as follows. Modify the startup script if necessary.
    service certificate/etc/grid-security/gfsd/gfsdcert.pem
    private key /etc/grid-security/gfsd/gfsdkey.pem
    When the -l option of config-gfsd is specified, the directory is /etc/grid-security/gfsd-LISTEN_ADDRESS instead of /etc/grid-security/gfsd.
    Since these path names are the same as those for GSI authentication, additional settings are not necessary for sites that have already completed GSI authentication settings.
    To use a service certificate for gfsd, the following settings are required in gfarm2.conf for clients and gfsd, and in gfmd.conf for gfmd. config-gfarm adds these settings by default. 
    spool_server_cred_type host
spool_server_cred_service gfsd
    These settings are also common to GSI, so sites that have already completed GSI authentication settings do not need to make any additional settings.

Settings specific to tls_sharedsecret authentication

On all client, gfmd, and gfsd hosts, a shared secret key must be placed in the .gfarm_shared_key file directly under each user's home directory.
The configuration of this file is the same as that of sharedsecret authentication, so please refer to the description of sharedsecret authentication.

Settings specific to tls_client_certificate authentication

Settings by the administrator

For each user, register the Subject DN of the client certificate as the fourth argument of the gfuser -c command in the format "/O=Company/OU=Division/CN=UserName".
This setting is also common to GSI, so additional settings are not required for sites that have already been configured for GSI authentication.

Settings by each user

  • When proxy certificates are used
    Proxy certificates created by GSI's grid-proxy-init command or the myproxy-logon command can be used without modification. Use these commands to create proxy certificates.
  • When proxy certificates are not used
    The user certificate and private key can be set by the tls_certificate_file and tls_key_file directives in the client's gfarm2.conf. The default file names, relative to each user's home directory, are as follows.
    user certificate .gfarm/usercert.pem
    private key .gfarm/userkey.pem
    These files are the same as those for GSI, so for sites that have already completed GSI authentication settings, simply create a symbolic link with the following command to complete the setup. 
    $ ln -s .globus $HOME/.gfarm

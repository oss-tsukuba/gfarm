Accessing Samba by Using SSH Port Forwarding

English | Japanese

1. Overview

If a Samba server is on a network reachable from an SSH server, and you can log in to the SSH server by SSH, you can access the Samba server. That is, from a Windows machine in an environment that normally cannot reach it, you can access Windows file sharing services and Samba across firewalls and the Internet by SSH, without VPN. This is done with the port forwarding feature of SSH. The procedure is simple.

Configuration example 1

  • Windows client: at the office, mobile, etc.
  • SSH server: at home, via port forwarding of a broadband router (or in a DMZ)
  • Windows file sharing: private network at home

With the above configuration, for example, you can access files on the Windows machine at home from outside.

As an application, by placing Samba and an SSH server in a Gfarm environment that is not accessible from outside, you can access Gfarm from outside.
For how to access Gfarm via Samba, see

  • by using Gfarm Samba plugin
  • by using gfarm2fs

Configuration example 2

  • Windows client: over the Internet, behind a broadband router at home, mobile, etc.
  • SSH server: gateway of the company (inside or outside)
  • Samba server: private network in the company
  • Gfarm: private network in the company

Configuration example 3

  • Windows client: behind the company firewall; a proxy server is required to access the Internet
  • Proxy in the company: SOCKS/HTTP proxy (SSH to outside via the proxy)
  • SSH server: gateway of another company
  • Samba server: private network in the other company
  • Gfarm: private network in the other company
Even in the above cases, you can access Samba and Gfarm across the Internet.
This can also be applied to other configurations, as long as there is a path reachable by SSH.

The following describes how to forward ports to Samba or Windows machines by SSH (independently of Gfarm).

2. Software

  • Windows machine (tested on 2000, XP, and Vista); the Administrator privilege is required
  • SSH client for Windows (for port forwarding); use one of the following (the latest version if possible)
    • PuTTY: https://www.chiark.greenend.org.uk/~sgtatham/putty/
    • Cygwin OpenSSH: https://www.cygwin.com/
    • PortForwarder: http://www.fuji-climb.org/pf/

3. Installing a virtual network interface

Prepare a network interface used as the forwarding source, in addition to the network interface currently in use. It does not need to be a physical interface; a virtual interface can be used as follows.
  1. Open the Control Panel.
  2. Open "Add Hardware".
  3. Click "Next".
  4. Select "Yes, I have already connected the hardware", and click "Next".
  5. Select "Add a new hardware device" at the bottom, and click "Next".
  6. Select "Install the hardware that I manually select from a list (Advanced)", and click "Next".
  7. Select "Network adapters", and click "Next".
  8. Select "Microsoft" and "Microsoft Loopback Adapter", and click "Next".
  9. Continue until the installation is completed.
  10. After the installation, open "Network Connections" from the Control Panel.
  11. Find the icon whose device name is "Microsoft Loopback Adapter".
  12. # It is convenient to rename the icon to an easily recognizable name such as "for SMB over SSH".
  13. Open its properties, and on the "General" tab, uncheck "File and Printer Sharing for Microsoft Networks".
  14. Keep "Internet Protocol (TCP/IP)" checked, select it, and click "Properties".
  15. Enter an IP address and subnet mask that do not conflict with other machines. You will probably use a private address range or the link-local address range (169.254.*.*). The following describes an example using 169.254.0.1/255.255.0.0. You do not need to enter the gateway and DNS fields.
  16. Open "Advanced". On the "WINS" tab, select "Disable NetBIOS over TCP/IP".
  17. Click OK to close each dialog.
  • Port 139/TCP (445/TCP on Vista) of the network interface normally in use is already used, so this method is used to obtain port 139 (445).
  • You can add more IP addresses on "Advanced" -> "IP Settings" tab -> "IP addresses", and use them as additional forwarding sources to use Samba at multiple sites at the same time.
  • It is convenient to map the IP addresses to names of your choice in the %windir%\system32\drivers\etc\hosts file.

4. Port forwarding settings

Using the local forwarding feature of SSH, forward port 139 (445 on Vista) of the virtual network interface to port 139 (445 on Vista) of a machine reachable from the SSH server. The following uses port 139; on Vista, read it as 445.

  • When forwarding ports through multi-hop SSH connections, intermediate ports can be other than 139, but both the entrance and the final exit must be port 139.
  • By changing the port number when forwarding, you can also run Samba on a port other than 139.

The following assumes this configuration.

  • Virtual network interface on the client configured above: "169.254.0.1"
  • Host name of the SSH server: sshserver.example.com
  • IP address of the Samba machine as seen from the SSH server: "192.168.1.234"
    • If the SSH server and the Samba machine are the same, "127.0.0.1" can also be used.
    • A name such as sambaserv.example.com can also be specified.

PuTTY

  1. Create and save an SSH session to sshserver.example.com, and make sure that you can connect.
  2. Restart PuTTY, and load the session again.
  3. Select "Tunnels" ("Connection" -> "SSH" ->).
  4. Enter "169.254.0.1:139" as "Source port" (the field is narrow) and "192.168.1.234:139" as "Destination", make sure that "Local" is checked, and click "Add".
  5. Save the session.

Cygwin OpenSSH or PortForwarder

Add a setting like the following to .ssh/config for Cygwin, or to the configuration file (.txt) for PortForwarder.

Example 
Host sshServerForSamba
HostName sshserver.example.com
User takuya
Port 22
LocalForward 169.254.0.1:139 192.168.1.234:139

5. Connecting

  1. Connect to the SSH server by the SSH client configured above.
  2. Open Explorer.
  3. Enter "\\169.254.0.1" in the address bar.
  4. # If you cannot connect, try the latest version of the SSH client.
  5. If a password is requested, enter the user name and password for the forwarded Windows or Samba machine.
  6. You can also map the shared folder to a network drive.

6. Disconnecting

  1. Right-click "My Computer", and open "Disconnect Network Drive".
  2. If the corresponding drive exists, select it and click OK to disconnect.
  3. After disconnecting, or if there is no corresponding drive, exit the SSH client.

7. Miscellaneous

  • Since only TCP is forwarded by SSH, this is easier and safer than VPN.
  • The communication performance depends on that of SSH. The cipher and compression modes also affect it.

8. For Linux (reference/comparison)

On Linux, you can directly access files under a Gfarm directory that is not directly accessible from your client, as follows. This is even easier.
  • On your client, mount the directory of the following server over SSH by using SSHFS.
  • On the SSH server machine that can access Gfarm, mount Gfarm by using gfarm2fs.
